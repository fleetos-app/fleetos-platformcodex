# FleetOS Feature Parity Audit

Source repo audited: `C:\Users\heman\Documents\subbies`

This audit uses the old FleetOS/Subbies repo only as product intelligence. Do not copy old code. Rebuild each valuable capability in the new Next.js, Supabase, RLS, RBAC, modular monorepo architecture with repositories, services, shared types, tests, and migrations.

## Roles Found In Old Product

| Role | Old routing/layout signal | New architecture mapping |
| --- | --- | --- |
| Admin / owner / ops | `AdminLayout`, `/admin/*` | Organization `owner`, `admin`, `ops_manager` under `/app` modules, with FleetOS internal `/admin` kept separate |
| Accounts | `AccountsLayout`, `/accounts/*` | `accounts` role with finance/accounting module |
| Subcontractor | `PortalLayout`, `/portal/*` | `subcontractor` role with subcontractor portal module |
| Client/customer | `ClientLayout`, `/client/*` | `client` role with client portal module, after core ops is stable |
| Mechanic | `MechanicLayout`, `/mechanic/*` | `mechanic` role with maintenance module |
| Public unauthenticated | `/report-incident`, `/mechanic-service`, `/truck-checkin` | Public intake endpoints with signed tokens, rate limits, audit logs |

## Immediate Parity Conclusions

- P0 value is operational: jobs, dispatch, runs, subcontractors, fleet, PODs, control tower.
- P1 value is safety/compliance and data trust: incidents, compliance hub, documents, audit history, temperature, work logs.
- P2 value is finance depth and portals: invoices, accounts, client portal, fuel, tolls, maintenance, reporting.
- P3 value is advanced ecosystem: live GPS, webhooks, demo mode, deeper automation, full email queue.

## Rebuild Principles

- Add migrations before application code.
- Keep organization tenancy and RLS on every tenant-owned table.
- Create one module per domain under `apps/web/modules/<module>`.
- Put database access in repositories, business logic in services, route/page code in app routes, and reusable UI in components.
- Add typed permission constants in `packages/rbac`.
- Use audit logs for create/update/approve/pay/import/public intake actions.
- Never reuse old generated files or component code directly.
